# El contexto como historial de decisiones

## Definición provisional

El contexto es el conjunto de decisiones, motivos, restricciones y consecuencias que permite comprender por qué una actuación o implementación es como es.

## Observación

Cuando un desarrollador consulta:

- git blame;
- commits antiguos;
- tickets previos;
- conversaciones;
- actas de reuniones;
- documentación histórica;

no siempre está buscando únicamente información técnica.

Con frecuencia intenta reconstruir decisiones pasadas y sus motivos.

## Consecuencia para TaskLab

El producto no debe limitarse a almacenar el resultado de una decisión.

Debe conservar, cuando sea relevante:

- la necesidad que la originó;
- la pregunta que intentaba resolver;
- las alternativas consideradas;
- quién tenía autoridad;
- la decisión tomada;
- su motivo;
- sus consecuencias;
- sus sustituciones posteriores.
