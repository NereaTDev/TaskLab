# Ready to Understand

Definición

Una tarea está Ready to Understand cuando un desarrollador puede comprender qué debe modificar sin depender de conversaciones adicionales.

No implica que la tarea esté lista para desarrollarse.

Implica únicamente que existe suficiente información para comprenderla.

Posibles criterios iniciales

- Estado actual descrito.
- Estado esperado definido.
- Regla de negocio identificada.
- Responsable funcional conocido.
- Diseño disponible si aplica.
- Criterios de aceptación definidos.

Esta definición evolucionará con futuras validaciones.
