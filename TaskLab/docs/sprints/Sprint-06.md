# Sprint 06

Estado

Completado

Objetivo

Identificar qué recibe realmente TaskLab, qué transforma y cuál debe ser el objeto raíz de su dominio.

Resultados

- Se descartó utilizar Ticket, Issue, Story o Task como objeto raíz.
- Se identificó la Necesidad como entrada fundamental del sistema.
- Se concluyó que una necesidad puede originarse en una persona, un sistema, una regulación, el mercado u otra fuente.
- Se descubrió que toda ejecución contiene decisiones, aunque sean pequeñas.
- Se identificó que las decisiones pueden depender de personas diferentes.
- Se introdujo el concepto de propiedad de la decisión.
- Se definió el contexto como el conjunto de decisiones que explica por qué una actuación o implementación es como es.
- Se formuló la primera cadena conceptual del dominio:
  Necesidad → Decisiones → Ejecución → Validación.
- Se concluyó que TaskLab debe hacer visibles las decisiones implícitas.

Próximo Sprint

Investigar cómo gestionan actualmente las organizaciones sus decisiones y localizar el hueco real que dejan las herramientas existentes.
